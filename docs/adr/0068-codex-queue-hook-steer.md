# ADR 0068: Codex親のSteer相当機能を公式キューとhookで提供する

状態: 採用。実装と隔離動作確認の段階であり、公開・利用端末への導入は別途行う。

## 背景

Node更新で中継の実行ファイルが消え、Codex Desktopの起動が終了コード127で失敗した。
ADR 0067で版別Nodeパスを修正したが、AitermがCodexの起動に介在する責務は残っていた。
オーナーはSteerまたは同等の機能を必須とし、機能を止める解決を却下した。

公式Codexの通常stdio起動には外部から接続するローカルsocketがない。
一方、公式の同期PostToolUseとStopは実行中の会話へ文脈追加・継続入力を渡せる。
[隔離試験](../evidence/codex-queue-hook-20260919.md)で公式キューとの組合せが成立した。

## 判断

回答は公式キューへ一度だけ投入する。実行中の親は公式hookでAiterm所有の回答だけを取り出し、
同じターンへ渡す。hookが受け取っていない回答は公式キューに残り、終了後に同じ会話を再開する。
起動launcherを新設せず、旧中継は新しいhookの登録・承認・読戻しの後で解除する。
これにより、AitermのNode・moduleが失われてもCodexの通常起動は維持される。

hook自身の承認は、公式APIが返したAiterm専用2件のkeyとhashに限る。
他製品のhook、承認、親のmodel、権限、認証は変更しない。承認省略flagは使わない。
同時hookの取得をfilesystemで一つに決め、取り出した本文の出力が不明な時は保存してunknownとする。
自動再送による二重処理は行わない。状態は既存のparent_deliveriesへ反映する。

## 挙動の差

- 実行中はツール実行後か最終応答の終了処理で同じターンへ渡る。
- 終了後の再開は公式キューの監視周期に従い、約10秒かかる場合がある。
- 長いStop継続入力はCodexの公式処理で抜粋と全文ファイルへの参照になる場合がある。
- 新しい方式のキューIDは、Steer相当の選択時も配送receiptに残る。
- 旧中継コードは移行と既存設定の互換のため保持する。新しい正規setupから中継を作らない。

ADR 0062・0063・0066は旧方式の判断履歴として保持する。
