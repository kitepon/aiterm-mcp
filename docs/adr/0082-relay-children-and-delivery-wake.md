# ADR 0082: 中継の直接の子を席のprocess数から外し、眠っている本体を起こす判定を持つ

状態: 採用。ADR 0080の「例外は1つ」を2つにする。

## 原因

BellTeamは、MCPを使う時だけ本体を起こす中継（`mcp-lazy`）の後ろにAitermを登録して、使われていない席のメモリを空ける。
中継ごしの登録で、今の作りに合わない所が2つ出た。

1. 中継は、道具を初めて呼ばれた時に本体（`dist/index.js`）を自分の下に起こす。起動完了の後に立つので
   `activity.post_startup_process_count`に入り、席が終わるまで残る。実物のCursor（2026-10-04、mcp-lazy 0.2.0）で、
   直結は道具を呼んだ後も0、中継ごしは1回呼ぶと1になり、60秒後も1だった。BellTeamは0の席だけを閉じるので、
   道具を一度使った席は二度と閉じない。
2. 終了した持ち主の配送を引き取るのは、起きている本体（5秒おき）。本体が眠っている席は引き取らない。
   mcp-lazy 0.3.0は、席を閉じると本体も終わらせる。待っている配送がある席を閉じると、同じ種類の本体が他に起きていない限り、
   次に誰かが道具を呼ぶまで、子の回答は確保されない。

## 判断

### 中継の直接の子は数えない。その下は数える

親の起動時のargvの先頭のbasenameが`mcp-lazy`で始まるprocessは、`post_startup_process_count`に入れない
（`mcp-lazy`、`mcp-lazy-0.3.0-7cdb9cc`、`mcp-lazy.exe`。大文字小文字を区別しない）。
中継が直接の子として起こすのは、登録されたMCPの本体と、先行起動の判定のprocessの2種類。どちらも中継の仕組みの一部で、
利用者の作業ではない。Codexの`codex-code-mode-host`と同じ扱いにする。

- 外すのは直接の子だけ。本体や判定の下で動くprocessは、今までどおり数える。
- 中継そのものは、今までどおりの扱い。harnessの起動時に立つので控えに入る。後から立てば数える。
- 親はOSのprocess表の親子関係で引く。Windowsで再利用された親PID（子より後に始まったprocess）は親として扱わない。
- 名前と親子関係は、mcp-lazyのREADMEに互換性の契約として書いてある。変える時は事前に調整する。

BellTeamの側で条件を変える案は採らなかった。BellTeamへ届くのは数だけで、本体と裏の作業を見分けられない。
数の意味はAitermが持つ。

### 起こすかどうかは、Aitermのコマンドが返す

`aiterm-delivery-wake --parent <codex|claude|cursor>`。その種類の親の配送の保存場所（この端末の子と別端末の子の2か所）を見て、
終了した持ち主（`owner.json`が`closed`、またはprocessが居ない）の下に記録が残っていればexit 0、無ければexit 1。
中継は、本体が眠っている間、これを本体と同じ環境で定期的に実行する。

- 親の種類は引数で受ける。本体は`initialize`の`clientInfo.name`で知るが、判定は中継から起こされ、それを受け取らない。
  登録はharnessごとに別のファイルなので、登録する側が書ける。
- 子processを起こさない。判定は中継の直接の子で、その子は孫になり、席のprocess数に入る。
  持ち主の生死は`process.kill(pid, 0)`で見る。pidの再利用は、Linuxでは`/proc`の開始時刻を`owner.json`の値と突き合わせる
  （`ps`の`lstart`と同じ値を、起動時刻と開始tickから作る。2秒までのずれは同じとみなす）。`/proc`の無いOSでは、
  pidがあれば生きている扱いにする。本体は起きた時に`ps`で照合するので、取りこぼしは「誰かが起きるまで遅れる」に留まる。
- 起こすのは1席だけ。同じ種類の席は全部が同じ判定を回すので、何もしなければ1件の配送で全席の本体が起きる。
  持ち主ごとの印（`<保存場所>/wake-claims/<持ち主の保存場所の名前>`のディレクトリ）を先に作れた判定だけがexit 0を返す。
  起きた本体はすぐ引き取り、記録が持ち主の下から無くなる。次の判定がその印を片付ける。
  引き取られないまま30秒過ぎた印は、次の判定が取り直してexit 0を返す（起こした席が、起きる前に閉じられた時）。
- 判定は記録の中身を読まない。配送の持ち主と引き取りの決まりは変えない。起きた本体が、今までどおり引き取る。

間隔は中継の設定（`MCP_LAZY_WAKE_INTERVAL`）で決まる。判定は1回がnodeの起動1回分。席を起こし直した時は、中継が
`notifications/initialized`の直後に1回実行するので、間隔を長くしても、起こし直した席の配送はすぐ引き取られる。

## 影響

- `aiterm.pty-observe-result.v1`の形は変えない。中継ごしの席で、数が小さくなる。
- binを1つ足す（`aiterm-delivery-wake`）。MCPの道具は増やさない。
- 配送の保存場所に`wake-claims`を足す。本体は読まない。旧版の本体と並んで動く。
