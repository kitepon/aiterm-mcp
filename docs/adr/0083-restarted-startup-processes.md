# ADR 0083: harnessが立て直した起動時のprocessを、起動完了の控えの物として扱う

状態: 採用。ADR 0080の「起動完了の後に立ったものは、作業でなくても数える」のうち、立て直しを数えるのをやめる。

## 原因

`activity.post_startup_process_count`は、起動完了の控えに無いprocessを数える（ADR 0080）。
harnessは起動の足場（MCP、language server）を自分で立て直す。控えた後に立て直されると、新しいprocessは控えに無く、
席が終わるまで数に残る。BellTeamは0の席だけを閉じるので、何もしていない席が閉じられない。

実物のCursor（2026-10-04、Cursor 2026.10.01、BellTeamのコンテナ）で、Cursorは起動時にstdioのMCPを立て、
最初のつなぎが全部済むと止めて立て直していた。普段は、起動を頼んで3.5秒で立ち、6.4秒で止め、7.5秒で立て直し、
10秒でAitermが入力受付を確かめる。控えには立て直した後の物が入る。
つながるのが遅いMCPが1つあると、立て直しは入力受付の後になり、控えには1回目の物が入る。その席は道具を一度も呼ばないまま、
立て直された数だけ残る。initializeへの返事を12秒遅らせるMCPを足した席で、直結は3、中継ごしは4（3席ずつ、3席とも）。
自然にも起きた（BellTeamの反映の直後、29回中2回、aitermとapproval-boxの2）。CPUを混ませるだけでは起きなかった。

## 判断

控えの物が終了していて、同じ親の下に、同じargvで立っているprocessは、その立て直しとして数えない。

- 起動完了の控えに、processごとの親（pid:開始時刻）とargvのdigestを足す（agent metadataの`startup_process_shapes`）。
  生argvは今までどおり保存しない。
- 親も立て直されている時は、立て直された親の下を見る（`npm exec`の下のlanguage serverのように、連なって立て直される物）。
- 終了した控え1つにつき、数えないのは1つまで。同じargvで2つ立っていれば、1つは数える。
- 控えの物が生きている間に同じargvで立ったものは、立て直しではないので数える。
- 立て直されたprocessの下で動くものは、今までどおり数える。
- 起動から何秒以内、という条件は付けない。harnessは後からでもMCPを立て直す（MCPが落ちた時、つなぎ直した時）。

数えすぎは「閉じない」側へ倒れる、というADR 0080の向きに対して、この判断は数えない側へ1歩寄せる。
取りこぼすのは、利用者の作業が、終了した起動時のprocessと同じ親の下で、同じargvで動いている時だけ。
起動時に居るのはharnessの足場で、利用者の作業と同じargvにはならない。

待ちを長くして控えを遅らせる案は採らなかった。何秒待てば足りるかは負荷で変わり、後からの立て直しには効かない。

## 影響

- `aiterm.pty-observe-result.v1`の形は変えない。立て直しがあった席で、数が小さくなる。
- agent metadataに`startup_process_shapes`を足す。無い記録（この版より前のAitermが起動したagent）は、今までどおり数える。
- `agent_launch`は、起動完了の時にOSのprocess一覧を1回多く読む。
