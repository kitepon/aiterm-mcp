# ADR 0097: turnを1つ終えた席への送信は、起動直後のための5秒の確かめを待たない

状態: 採用。

## 原因

起きていて動いていないCodexの席へ`pty_send`で新しいturnを送ると、受け付けを返すまで毎回5.7秒かかっていた。

- 連携元（BellTeam）の本番の記録（2026-10-06〜07、0.55.2、30通）: Codexの席への新しいturnは17通が
  5,686〜5,858msに揃っていた。同じ席でも、動いているturnへの差し込みは0.43〜0.47秒。Claudeの席への新しいturnは
  0.67秒。
- 連携元は、`pty_send`が受け付けを返すまで、アプリへ応答を返さない。iPhoneのアプリは、待っている間に画面を
  消されるとiOSに止められ、届いている送信を失敗と表示していた。
- 実物で測った内訳（このコンテナ、Codex 0.160.1、専用の置き場）: 5.60〜5.62秒のうち5.0秒が入力受付の確かめで、
  残りは貼ってからEnterまでの250msと、送った後の残りの確かめの250msなど。席は待っている間ずっと入力待ちだった。
  Grok 1.0.46の席は5.60秒、Cursor 2026.10.01の席は5.36秒で、同じ待ちを通っていた。

入力受付の確かめは、画面を500msおきに読み、11回続けて入力待ちなら通す（ADR 0014）。起動の途中に一瞬だけ
入力欄が出て、そこへ送った最初の文が消えた事故のための決まりで、ADR 0014は「follow-up、既にbind済みturnは
変更しない」と書いている。その後、Codexの完了を記録（rollout）で読む形へ移した時（ADR 0022）に、2通目以降も
「止まっている事を確かめてから記録の境界を切る」ために同じ確かめへ通した。GrokとCursorも同じ道に乗った。
止まっている事の確かめに5秒の連続は要らないが、11回の決まりがそのまま付いて来ていた。Claudeの2通目以降は、
自前のturnの印で差し込みか新しいturnかを決めていて、この確かめを通らない。

2通目以降で5秒の連続が結果として守っていたのは、turnの終わり際である。Codexは最後の回答を流している間、
動作中の行を出さない。その間に届いた文は、5秒の内にturnが終われば、終わった後の新しいturnとして送られていた。

## 判断

送信の前の入力受付の確かめで、席のharnessが自分の記録で「この起動でturnを1つ終えていて、次のturnを始めて
いない」と示している時は、100msおきに2回続けて「画面が入力待ち」かつ「記録の上でturnが無い」なら通す。
記録で示せない時は、今までどおり500msおきに11回。

- 記録は、この起動に結び付いた物だけを読む。起動直後の席には記録が無いので、最初の文は今までどおり11回を待つ。
  - Codex: root rolloutの最後の境界が`task_complete`か、Escで止めた時の`turn_aborted`（`reason`が`interrupted`）。
    後ろに`task_started`が無い事。他の理由の`turn_aborted`は、実物で見ていないので数えない。
  - Grok: `events.jsonl`の最後の境界が、完了と数える`turn_ended`。差し込みの継ぎ目（`cancelled`かつ`send_now`）は
    完了と数えない。
  - Cursor: transcriptの末尾が`turn_ended`。
- 分からない時は「終わった」と数えない。記録が無い、書いている途中の行がある、境界が末尾の1MiBに無い、読めない、
  のどれも11回の確かめへ回す。
- 記録の上でturnが動いている間は、画面が入力待ちに見えても短い道を使わない（今までと同じ動き）。待っている間に
  turnが終われば、そこから短い道で通す。境界は、終わったturnの後ろに切られる。
- 確かめている間に記録の上でturnが始まったら、短い道をやめて11回を数え直す。
- 短い道を使うのは、文を送る前の確かめだけ。起動時promptの確かめ、設定変更（`agent_configure`）の後の確かめ、
  利用上限のmodalやpanelを閉じた直後の確かめは、今までどおり11回。

「入力受付状態になりません。文字列は送信していません。」と言い切れるのは、確かめが貼る前にあるからで、確かめの
長さには頼っていない。この順番は変えていない。

## 退けた案

- **回数を一律に減らす（11回を2回へ）**: 起動直後の守り（ADR 0014）と、turnの終わり際の守りが無くなる。
- **動いているかどうかを、画面でなく記録だけで決める**: 差し込みか新しいturnかの振り分けが変わる。中断された
  turnは記録に終わりが残らない事があり、その席への送信が全部差し込み（完了の知らせ無し）になる。Codexが回答を
  流している間を止まっていると読む件は、別に扱う。
- **貼ってからEnterまでの250msと、送った後の残りの確かめを削る**: Enterの取り落としと、入力欄に残った文を
  見つけるための待ちで、今回の5秒とは別の守りである。
- **連携元が、保存した時点でアプリへ応答を返す**: 連携元の応答の形の話で、Aitermの外にある。

## 影響

- 止まっている席への2通目以降の文は、受け付けが約5秒早く返る（下の実測）。
- 起動直後の最初の文、止まっている席を起こした後の最初の文は変わらない。
- 記録の上でturnが動いている間（Codexが回答を流している間など）に届いた文は変わらない。
- 前のturnが終わった直後に届いた文は、今までは5秒後、これからはすぐに、新しいturnとして送られる。
- 道具の返りの形、断りの文面は変わらない。

## 確かめ

- 試験: 確かめの回り方（記録で終わっていれば2回・100ms、示せなければ11回・500ms、途中でturnが始まれば数え直し、
  待っている間に終われば短い道、画面が入力待ちでなければ通さない）。CodexとGrokの記録の読み方（記録なし、turnなし、
  動いている、終わった、次が始まった、書いている途中、境界が読む範囲に無い、別の起動の記録）。偽のCodexの席で、
  起動直後は短い道を使わず、turnを1つ終えた後は使い、記録でturnが動いている間は使わない事
  （`test/settled-turn-ready.test.mjs`、`test/core-agent.test.mjs`）。
- 実物（このコンテナ、専用の置き場、完了の知らせの数ms後に続けて送る）:

  | 席 | 0.55.3 | 直した版 | 最初の文 |
  | --- | --- | --- | --- |
  | Codex 0.160.1 | 5.60〜5.62秒 | 0.66秒（6通） | 5.66秒 |
  | Grok 1.0.46 | 5.60秒 | 0.65秒（4通） | 5.60秒 |
  | Cursor 2026.10.01 | 5.36秒 | 0.41秒（4通） | 5.50秒 |

  どの文も新しいturnとして返り、完了で読めた回答はその文の物だった。
- 実物（前の文からの間を変えて次の文を送る。0.55.2と直した版）: 動いている最中の文は、どちらの版でも差し込みに
  なった（Codex・Grok）。前のturnが終わった後の文は、直した版では0.4〜0.7秒で新しいturnになり、回答はその文の物
  だった（Codex 3通、Grok 4通、Cursor 22通）。
- 実物（Codexが400行の回答を流している最中に次の文を送る）: 0.55.2と直した版で同じ結果。受け付けは5.6〜5.7秒、
  返りは新しいturn、Codexは同じturnへ取り込み、完了は2つとも同じturnで届いた。

- 実物（Codexのturnを途中でEscで止めた後に次の文を送る）: 記録には`task_started`の後に`turn_aborted`（`reason`は
  `interrupted`）が残った。次の文の受け付けは0.68秒（直す前の決まりでは5.65秒）で、回答はその文の物だった。
- 3つのOSの実物（rabbit・macbook・fox、専用の置き場。完了の知らせの数ms後に続けて送る。0.55.3と直した版）:

  | 端末 | 席 | 0.55.3 | 直した版 |
  | --- | --- | --- | --- |
  | rabbit（Linux） | Codex 0.160.0 | 5.64秒 | 0.69秒 |
  | rabbit | Grok 1.0.46 | 5.63秒（最初の文） | 0.69秒 |
  | rabbit | Cursor 2026.10.01 | 5.85秒（最初の文） | 0.65秒 |
  | macbook（Mac） | Codex 0.160.1 | 5.75〜5.78秒 | 0.70〜0.78秒 |
  | macbook | Grok 1.0.46 | 5.71秒（最初の文） | 0.72秒 |
  | macbook | Cursor | 5.84秒（最初の文） | 0.69秒 |
  | fox（Windows） | Codex 0.160.0 | 6.46秒 | 1.40秒 |
  | fox | Cursor 2026.10.01 | 8.05秒（最初の文） | 3.2秒 |

  GrokとCursorの「0.55.3」の欄は、直した版で送った最初の文（今までと同じ11回の確かめを通る）の値。どの文も
  新しいturnとして返り、回答はその文の物だった。foxのGrokは、文を受け付けてもturnが終わらない（前からある端末の側の
  不調）。記録に終わったturnが無いので、直した版でも4通とも11回の確かめを通った（6.4秒）。

## 見ていない事

- Codexの利用上限のmodalが、turnの終わりから遅れて出る場合。modalが出ている画面は入力待ちと読まないので送らないが、
  2回の確かめ（100ms）の後に出るmodalは、今までの5秒より見つけにくい。
- 長く動いた席の、大きな記録での読む時間。末尾の1MiBだけを読む。
- Codexの`turn_aborted`の、`interrupted`以外の理由。
- WindowsのGrokの、2通目以降の文（foxのGrokはturnが終わらない）。
