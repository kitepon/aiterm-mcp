# ADR 0100: Windowsで、Claude Codeの席を止める前に、自分で終わる機会を与える

状態: 採用。

## 原因

`pty_close`は`kill-session`（Windowsはpsmux）でsessionを止める。POSIXのtmuxは、画面のprocessへ切断の合図（SIGHUP）を送り、
Claude Codeは片付けて終わる。Windowsのpsmuxは合図なしで止める。

- 実物（Windows、Claude Code 2.1.291・2.1.292）で、`pty_close`されたClaude Codeは、会話終了のhook（SessionEnd）を走らせなかった。
  同じ席へ先に`/exit`を送ってから閉じると走る。LinuxとmacOSは、`pty_close`の0.4秒後に走る（reasonは`other`）。
- 困るのは、会話終了のhookに頼る道具（常駐processを片付ける物など。会話が終わった事を知らず、時間切れまで残る）。

## 決めた事

Windowsで、Claude Codeの席を`pty_close`する時、sessionを止める前に、Claude Codeへ終了を頼む。

1. **条件**: 席がClaude Codeで、そのprocessが生きている時だけ。別processの待機・送信の途中で閉じられない席は、今までどおり何も送らずに断る。
2. **頼み方**: 入力待ちの席へ、C-cを間を空けずに2回（間は0.2秒）送る。Claude Codeは1回目で「Press Ctrl-C again to exit」を出し、
   すぐの2回目で会話終了のhookを走らせて終わる。この受付は短い（実物で、間0.3〜0.7秒の2回は通り、2.2秒の2回は切れた）。
3. **入力待ちでない席**（動いている番など）: 先にC-cを1回送り、入力待ちに戻るのを最大1.5秒待つ。このC-cは番を止めるのに使われ、
   終了の受付にならない。その後に2回送る。
4. **待ち**: 2回目の後、processが終わるのを最大4秒待つ。終わっても終わらなくても、その後は今までどおりsessionを止める。
5. **待ちは同期のまま**。待つ間にほかの呼び出しを通すと、閉じかけの席へ送信が入る。
6. 席の観測や鍵の送信に失敗した時は、何も頼まずに今までどおり止める。閉じる事を妨げない。
7. POSIXは変えない（tmuxが切断の合図を送る）。Codex・Grok・Cursorの席も変えない。返りの形（`closed`／`already_closed`）も変えない。

`pty_close`は、WindowsのClaude Codeの席でだけ遅くなる。実物では、入力待ちの席で約2.3秒、動いている番の席で約3.2秒。
終わらない席の上限は、席の観測の時間に約5.7秒を足した長さ。

## 取らなかった形

- **`/exit`を送る。** 入力欄が空で止まっている時しか効かない。Aitermの相関つきの席では、文の送信は新しいturnとして数えられる。
- **待ちを非同期にする。** 上の5のとおり。`pty_close`は今まで、ほかの呼び出しを挟まずに終わっていた。
- **Codex・Grok・Cursorの席にも同じ事をする。** 困っているのはClaude Codeの会話終了のhook。ほかの席で確かめた事が無い。
- **psmuxの側で合図つきで止める。** Aitermの外の変更になる。

## 及ばない所

- 入力欄に文が残っている席は、1回目のC-cが文を消すのに使われ、2回では終わらない。その時は今までどおり止まる（hookは走らない）。
- 確認の画面（承認など）が出ている席でC-cがどう効くかは、実物で見ていない。終わらなければ、今までどおり止まる。

## 確かめ

- `test/claude-exit-before-close.test.mjs`: 鍵と待ちの順番（差し替えた時計で、入力待ち・動いている番・戻らない席）。
  鍵を受けて自分で終わる偽の席で、`pty_close`の道が切断の合図より前に鍵で終わらせる事、鍵で終わらない席を待った後に止める事、
  既定のPOSIXとClaude Code以外の席へは鍵を送らない事。
- 実物（Windows、Claude Code 2.1.292、project設定に会話終了のhookを置いた試験用のフォルダ）: 入力待ちの席は`pty_close`が2.3秒で
  返り、その間にSessionEnd（reasonは`prompt_input_exit`）が走った。60秒の命令の途中の席は3.2秒で返り、同じく走った。
  直す前は、どちらも走らない。
