# ADR 0107: Codexの警告の画面が開いている席を、入力待ちと読まない

状態: 採用。

## 原因

Codexは、足元に「⚠ N warnings · f2 to view」を出す。F2を押すと、入力欄の場所に警告の画面が開く。

```
  Warnings · 1 of 3 · Startup

  Running without the shared background server: command-line configuration
  overrides (-c, --enable, --disable, or --search) requires embedded mode.

  k keep & next · esc dismiss & close · ^o copy · ←/→ warning · ↓ scroll
```

Codex 0.160.0にも同じ画面がある（鍵の案内は`^o copy`でなく`ctrl+o copy`）。
開いている間、入力欄と足元（modelの行、`? for shortcuts`）は描かれず、鍵はこの画面が受ける。番が動いていても、動作中の行は隠れる。
貼り付けた文は入力欄へ入らず、どこにも残らない。

- Aitermは、入力欄の行頭の印を`›`か`>`で探していた。起動の見出し（`>_ OpenAI Codex (v0.161.0)`）の`>_`もこれに当たる。
  見出しが画面に残っている席（起こしたて、`/new`・`/clear`の直後）では、入力欄が無くても「見出しがある・入力欄がある」と読んだ。
- その席へ`pty_send`すると、`pty_observe`は`idle`・`composer_ready`、送信は`agent_dispatch`を返した。文は警告の画面に吸われ、
  turnは始まらず、完了は来ない（Codex 0.161.0の実物で確かめた。2026-10-08）。送った文が残らないので、送信後の残り方の確かめも通る。
- 見出しが流れた後の席では、足元が隠れてCodexの画面と読めず、`unknown`・`unrecognized_screen`になる。送信は30秒待って
  「入力受付状態になりません。文字列は送信していません。」で断っていた。こちらは文を失わない。

## 決めた事

1. 入力欄の行頭の印から、起動の見出しの`>_`を外す。見出しだけの画面は入力待ちではない。入力欄（`›`、古い描画の`>`）がある時だけ入力待ちと読む。
2. 警告の画面を、応答の要る画面（modal）と同じに数える。見分けるのは、鍵の案内の行（`esc dismiss`で始まる案内を持つ行）と、
   見出し（`Warnings · N of M`）。入力欄より後ろにある時だけ、今の画面として数える（今までのmodalと同じ決まり）。
3. 返りは、前からある物だけを使う。
   - `pty_observe`: `blocked`・`unknown_dialog`。
   - `pty_send`: 待たずに、今までと同じ文面で断る（「…入力受付状態になりません。文字列は送信していません。…」、末尾は`state=blocked reason=unknown_dialog`）。
     番が動いている席・回答を流している席でも同じ（差し込みの道へは回さない）。
4. Aitermは警告の画面を閉じない。`Esc`は「その警告を消して閉じる」で、席の前の人が見ている物を変える。閉じるのは開いた人。
5. 変えない物: 引数、返りの項目、断りの文面、警告の画面が開いていない席の読み（入力待ち・動作中・承認・上限の画面）、起動の読み。

## 取らなかった形

- **警告の画面だけを足す（見出しの印はそのまま）。** 警告の画面は直るが、見出しが残る席で入力欄が別の画面に置き換わった時に、
  同じ読み違いが残る。Codexが新しい画面を足すたびに当たる。
- **見出しの印だけを外す。** 起こしたての席は30秒待って断るようになり、文は失わない。ただし、会話に製品名があり、前の依頼文
  （`›`で始まる行）が画面に残る席では、警告の画面が開いていても入力待ちと読める。画面そのものを見分ける方が確か。
- **Aitermが`Esc`で閉じてから送る。** 上の4。警告を1件、席から消す。
- **`pty_observe`へ新しい理由の名前を足す。** 呼ぶ側がAitermの道具で出来る事（承認・選択）が無い。知らない画面と同じ扱いで足りる。

## 及ばない所

- 入力欄の印は、会話に残る前の依頼文（`›`で始まる行）にも当たる。足元（modelの行）が描かれたまま、入力欄だけが知らない画面に
  置き換わる形がCodexに足された時は、その画面を足すまで入力待ちと読む。今のCodex（0.160.0・0.161.0）に、その形は見つけていない。
- 回答や依頼文に同じ鍵の案内の行が書かれていても、その下に入力欄がある席は入力待ち（試験にある）。入力欄が画面に無い席
  （起動の途中など）で、その行が最後にある時は、警告の画面と読む。
- 警告の画面が自分で開く事は無い（人がF2を押した時だけ）。BellTeamの席では誰も押さない。

## 確かめ

- `test/harness-pane-observation.test.mjs`: 実物の画面（起こしたての席・番が動いている席・回答を流している席・会話に製品名がある席）が
  `blocked`・`unknown_dialog`になる事。閉じた後の入力待ち、動いている番の読み、案内の行が会話にあるだけの席の入力待ち。
  見出しだけの画面が入力待ちにならず、入力欄が出れば入力待ちになる事。直す前の版では2件とも落ちる。
- 実物（公式のCodex 0.161.0＋偽のmodel）: 警告の画面を開いたままの席へ、止まっている時・番が動いている時・回答を流している時に送る。
  3通りとも0.03秒で断られ、画面に文は打たれない。閉じた後の文は新しいturnとして完了まで届く。普段の14場面は、直す前と同じ返り
  （起動は6.28秒で同じ）。Codex 0.160.0でも、3通りの断りと、起動・普通のturn・回答を流している間の差し込みを確かめた。
