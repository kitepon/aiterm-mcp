# ADR 0109: Windowsで、画面の無いlogonで立てた端末の本体を、画面のある側から問えるようにする

状態: 採用。psmuxが直しの入った版を公開するまでの手当て。

## 原因

Windowsの端末はpsmuxで動かす。psmux 3.3.8は、どの命令でも（`psmux -V`でも）最初に、端末の控え（`~/.psmux`の`port`・`key`・`pid`・`sid`）を見回る。
控えに書かれた本体のprocessを開けない時は「本体は終わっている」と読んで、その端末の控えを消す（psmux #650、`pid_anchor_verdict`）。

sshで入った側やserviceの下（Terminal Servicesのsession 0）で立てた本体を、同じ利用者の、画面のある側の普段の権限のprocessは開けない
（`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`が`ERROR_ACCESS_DENIED`）。逆向きは開ける。
つまり、画面のある側でpsmuxが1回呼ばれるたびに、画面の無い側で立てた生きている端末の控えが全部消える。
本体は5秒以内に控えを書き戻すが、その間、端末は一覧に出ない。その間に画面の無い側でpsmuxを呼ぶと、
「控えの無い本体」を止める見回り（10秒より古い本体が対象）に当たり、端末ごと止められる事がある。

- 実物（Windows 11、psmux 3.3.8 `66cf613`、2026-10-11）。sshの側から`remote`付きで立てた素の端末で、画面のある側のタスクが`psmux -V`を1回呼ぶと、
  0.13秒後に控えが4つとも消え、0.9〜3.7秒後に戻った。同じ利用者・普段の権限のタスクから本体は開けなかった（error 5）。
  その間、sshの側のAitermは「paneの活動観測を取得できません」と`missing / session_missing`を返した。
- ほかの席が画面のある側で動いている端末では、何もしなくても15秒の間に3回消えた。
- sshの側で立てたGrokの席は、4回中2回、文を送った20秒ほど後に本体が終わり、席が消えた（本体が先に終わり、Grokはその後）。
  1回は一度だけ`missing`になって戻った。止めたのが上の見回りである事は、psmuxの源と順番からの見込みで、止めた瞬間の記録は取れていない。
- CIのWindowsのrunnerはserviceの下（session 0）で動く。同じ条件に当たる。

psmuxのmasterでは直っている（#650、2026-09-13）。公開された版は3.3.8（2026-08-18）が最後で、wingetで入るのもそれ。

## 決めた事

1. **端末を立てた直後に、本体のprocessへ「同じ利用者が名前を問う権利」だけを足す。** 足すのは`PROCESS_QUERY_LIMITED_INFORMATION`（0x1000）1つ。
   画面のある側のpsmuxが本体を開けるようになり、控えを消さない。書き込み・読み出し・終了の権利は足さない。
2. **足すのは、psmuxが3.3.8で、画面のあるlogonの印（`SESSIONNAME`）が無い時だけ。** 印がある所（アプリや端末から起こしたAiterm）では、何も起こさない。
   印が無いのは、ssh・serviceの下と、画面のある側のタスク。どちらかは、足す側のscriptがsessionの番号で見分ける。
   画面のある側のタスクと分かったら、そのprocessでは以後問わない。
3. **足した後、控えが戻っている事を確かめてから、端末を使い始める。** 足す前の一瞬に消されていた時のため。待ちは、本体のpidを問う分と合わせて10秒より短い
   （立てて10秒以内の本体は、控えが無くても止められない。Aitermの端末は毎回新しい本体で立つ）。
4. **失敗しても端末は使わせる。** 足せなかった時は、理由を1行だけstderrへ書く（`PSMUX_SERVER_ACCESS_NOT_GRANTED`）。
5. **psmuxが直しの入った版を出したら、この手当ては自分から止まる。** 3.3.8以外では動かない。最低版を上げる時に、作りごと消す。

足す道具はWindows付属のPowerShell（5.1）で、窓は出さない。sshの側で端末を1つ立てるたびに約0.35秒かかる（実測324〜388ms）。

## 取らなかった形

- **psmuxの置き場を、画面の無い側だけ別にする（`PSMUX_DATA_DIR`）。** 控えは消されなくなるが、sshの側から、画面のある側で立てた席が見えなくなる。今は見えている。
- **画面の無い側では端末を立てず、画面のある側のタスクへ頼む。** 人がlogonしていないと立たない。作りも大きい。
- **一覧から消えた時に待ってやり直すだけ。** 読み違いは減るが、止められる事は防げない。

## 確かめ

- `test/tmux-runtime.test.mjs`: 要る・要らないの決め方、足す権利が0x1000だけである事、控えが戻るまでの待ち、失敗しても投げない事。
- `test/pty-observation.test.mjs`（Windowsだけ）: 実物の端末で、手当てが失敗しない事。CIのrunner（service）では実際に足す道を通る。
- 実物（fox、枝の版をsshで起こす）: 画面のある側のタスクから本体を開けた。`psmux -V`を2回呼んでも、ほかの席が動いていても、62秒の間、控えは1度も消えなかった。
  Grokの席は、文を送ってから200秒、3秒おきに問い続けて1度も`missing`にならず、最後まで残った。

- 実物（fox、画面のある側のタスクから、consoleを持たない切り離したprocessで端末を1つ立てて閉じる）: 新しく見えた端末の窓は、
  公開版（0.58.1）が5、この手当て入りも5。手当ては窓を増やさない（本体のpidを問う命令と、PowerShellは、窓を隠して起こす）。
  consoleを持たないprocessからpsmuxを呼ぶと窓が出る事そのものは、前からあり、この変更では直していない。

## 残る事

- 更新の前に立てた端末には効かない。
- Aitermを通さずにsshの側で立てたpsmuxの端末は、今までどおり消される。
