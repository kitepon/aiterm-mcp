# ADR 0115: pushのCIは、同じcommitの全テストがもう通っている環境を流さない

状態: 採用。

## 原因

公開の前に、枝をpushして手動実行（`workflow_dispatch`、`environment=all`）で3環境の全テストを通し、通ったcommitをmainへ早送りしている。
mainのpushは同じcommitなのに、変更分類がまた3環境を選び、同じ試験がもう一度走っていた。

- 2026-10-12の実物: commit `7713251b`は、手動実行 38194000978（Windows 12分22秒）が通った直後に、pushの実行 38194920001（Windows 12分5秒）が
  同じ試験を流した。commit `7536bb78`も同じ（38185599311 → 38186707077）。
- Windowsの分は、利用者が普段使う端末のrunnerで走る。同じcommitの2回目は、何も新しく確かめずに、その端末を12分使っていた。

## 決めた事

変更分類（`scripts/product-ci-plan.mjs plan`）は、pushの時、GitHubへ同じworkflow・同じcommitの実行を聞く。
手動実行か定期実行で、環境のjob（`full (<環境>)`）が成功している環境を、選んだ環境から外す。

1. **数えるのは手動実行と定期実行だけ。** この2つは、選んだ環境で必ず全テストを回す（`createPlan`）。push・pull requestは試験を依存から絞る事があるので、
   通っていても数えない。
2. **環境ごとのjobの結果で数える。** ほかの環境が落ちた実行でも、通った環境は同じcommitの全テストが通っている。落ちた環境だけを
   手動実行で流し直した時は、その分を足して数える。
3. **全部の環境が外れた時は、試験のjobを起こさない**（空のmatrixは起こせない）。変更分類は、外した環境と実行の番号を`prior_full`へ出す。
   関門（`verify`）は、「製品の変更」で試験のjobがskipでも、環境が空で`prior_full`に実行がある時だけ通す。訳の分からないskipは、前と同じに断る。
4. **聞けない時は流す。** GitHubの口が失敗した・答えが読めない・GitHub Actionsの外で動いている時は、何も通っていない物として、選んだ環境を全部流す。
   訳はCIの記録へ出す。
5. 手動実行と定期実行そのものは、同じcommitがもう通っていても、頼まれた環境を全部流す（流し直したい時の口を残す）。

変更分類のjobは、実行とjobの一覧を読むために`actions: read`を持つ（`ci.yml`と`product-full-ci.yml`）。読むだけで、書く口は足していない。

## 確かめ

- `test/product-ci-plan.test.mjs`: 数え方（手動・定期・1環境だけ・落ちた環境・動いている最中・push・別のcommit・別のworkflow）、
  GitHubの口を模したserverでの計画の出力（全部外れる・一部だけ外れる・pushの成功は使わない・口の失敗・つながらない・手元）、関門の受け方と断り方、
  workflowの条件。
- 本物のGitHubの記録へ、読むだけで流した（2026-10-13）: commit `7713251b`のpushは、3環境とも実行 38194000978 で成功済みと読み、環境が空になる。
  公開のcommit `82c9760`（手動実行が無い）は、前と同じ計画になる。tokenなしでも同じ答え（公開repository）。

## 変えなかった事

- tagの公開。ほかのeventのCIの結果を待たず、mainの祖先である事だけを確かめる。
- 変更分類の環境の選び方と、試験の絞り方。
- 関門が、分類の失敗と、選んだjobの失敗・取消を断る事。

## 残る事

- 枝の手動実行が終わる前にmainへpushすると、まだ成功していない環境は外れず、同じ試験が並んで走る。手動実行が終わってから早送りする。
- 同じcommitの手動実行が10件より多い時は、新しい10件だけを見る。
