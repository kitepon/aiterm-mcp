# ADR 0117: Claude Codeの席へ打つ前に、利用枠の選ぶ画面を閉じる。見覚えの無い選ぶ画面には打たない

状態: 採用。

## 原因

実被弾（2026-10-13）: Claude Codeの週の利用枠に当たって3つの席の番が止まった。利用者が枠を解いてから「再開しろ」と送った文が、
3席とも会話へ入らなかった。呼び手の記録は「受け付けた（実行中）」のままだった。

Claude Code 2.1.296は、枠に当たると番をAPIエラーで終え、自分で`/rate-limit-options`を開く。入力欄の代わりに選ぶ画面が出る
（止まった席の端末の記録から作り直した画面）。

```
❯ /rate-limit-options
────────────────────────────────────────
  What do you want to do?

  ❯ 1. Stop and wait for limit to reset
    2. Wait here, then continue automatically at Oct 16, 8am
    3. Switch to usage credits
    4. Upgrade your plan

  Enter to confirm · Esc to cancel
```

Aitermは、Claude Codeの席へ（起動直後の1通目を除き）画面を確かめずに「貼り付け＋Enter」を打つ。Claude Codeは動いている間も入力欄で
文を受けるので、入力受付の関門を通していない（`dispatchAgentTurnInLock`の関門は`meta.kind !== "claude" || claudeColdStart`の時だけ）。

実物の席（2.1.296。枠に当たっていない時に`/rate-limit-options`を手で開くと、2の行が無い3行の同じ画面が出る）で確かめた、選ぶ画面の動き:

- 貼り付け（文字でも数字でも）は捨てる。続くEnterは選択中の行（1番）を選び、画面が閉じる。文はどこにも残らない。
- **打鍵の数字は、Enter無しでその番を選ぶ。打鍵の「j」「k」は選択を動かす。**
- Escは、何も選ばずに閉じ、空の入力欄へ戻る。

つまり、選ぶ画面が出ている席へ送った文は消え、Aitermは打った控え（`agent_dispatch`）を返す。その送信が予約した番の印は残る。
実被弾の席では、次に届いた文は、席が入力待ちなのに差し込み（`agent_steer`）の道で入っていた（印と控えのfileの時刻が、消えた送信のままだった）。呼び手が渡す前置き（`preface`、ADR 0099）は打鍵で入るので、数字や「j」を
含む前置きは、別の番（枠の最中の3番は別払いへの切り替え）を選びうる。

今の版（0.58.4）と直した版を、動いていた本物の席で比べた（選ぶ画面を開いてから`pty_send`）: 今の版は`agent_dispatch`を返して文が消え、
直した版は`pane_input_recovery: ["claude_rate_limit_menu_closed"]`を返して席が答えた。

## 決めた事

1. **今開いている選ぶ画面を読む（`claudeLiveSelectMenu`）。** 画面の最後の行が案内（`Enter to confirm · Esc to cancel`）で、その上に番号の行が
   ある時を、開いていると数える。開いている間は入力欄も足元の行も描かれない。会話欄に残った同じ文や引用の下には入力欄と足元の行が描かれるので、
   最後の行を見れば見分けられる。見出しが`What do you want to do?`で、`Stop and wait for limit to reset`の行がある物を、利用枠の選ぶ画面と数える。
2. **agentの席への送信の頭（`sendAgentMessageInLock`。新しいturnと差し込みを振り分ける前）で、Claude Codeの席だけ、この読みを通す。**
   描き直しの途中の1枚で打たないよう、0.25秒おいた2枚目にも同じ画面がある時だけ扱う。
   - 利用枠の選ぶ画面: Escで閉じ、閉じたのを見てから、今までどおり送る。返りの`pane_input_recovery`に`claude_rate_limit_menu_closed`を入れる。
     枠が解けていれば文は普通に入る。解けていなければ、番はAPIエラーで終わり（完了待ちは今までどおり`error`と文面を返す）、選ぶ画面がまた出る。
     3秒で閉じない時は、`CLAUDE_RATE_LIMIT_MENU_NOT_CLOSED`で断る（打ったのはEscだけ）。
   - 見覚えの無い選ぶ画面: 何も打たずに`CLAUDE_SELECT_MENU_OPEN`で断る。見出しを添える。
   - どちらの断りも、文中に「文字列は送信していません。」を含める（連携元が未送信を見分ける決まり）。
3. **変えない物**: 選ぶ画面が出ていない席への送信（1byteも変えない）。起動直後の1通目の入力受付の関門。`agent_configure`（頭の関門が、
   選ぶ画面を入力待ちでないと読んで、元から断る）。`pty_close`（文字を打たない）。枠で終わった番の完了待ちの返り（`error`）。
   `preface`の口と、既にある断りの文面。

## 取らなかった形

- **利用枠の選ぶ画面でも、打たずに断る。** 枠を解いた後に送った文が届かず、席は誰かが画面を閉じるまで塞がったままになる。Aitermが管理する
  Claude Codeの席へは、公開の口からEscを打てない（`pty_key`はC-cだけ）ので、閉じられるのはAitermだけ。
- **見覚えの無い選ぶ画面もEscで閉じる。** Escの意味が画面ごとに違う（起動時の確認ではEscが終了になる物がある）。確かめた画面だけを閉じる。
- **Claude Codeの席にも、ほかのharnessと同じ入力受付の関門を毎回通す。** 動いている間の差し込みは、入力待ちでない画面へ打つのが正しい動き。
  関門を通すと差し込みが出来なくなる。
- **1番を選んで閉じる（Enter）。** 今の実害の無い閉じ方と同じだが、番号の並びは枠の状態で変わる（枠に当たっていない時は2番が別払い）。
  何も選ばないEscにする。
- **送った文が会話へ入った事を、送信の返りで確かめる。** 席の記録を読む仕組みが要る別の仕事。今回は、消える訳そのものを除く。

## 確かめ

- `test/claude-rate-limit-menu.test.mjs`: 実物の画面2つ（枠の最中の4行、手で開いた3行）と、閉じた後・引用・見出し違いの読み。
  偽の席が受けた生のbyteで、Escが文より先に1回だけ入る事（前置きつきも）、閉じない時と見覚えの無い画面では文が1byteも入らない事、
  選ぶ画面が無い席への送信が今までと同じ事。
- 本物の席（Linux、Claude Code 2.1.296、動いていた席で選ぶ画面を開いてから送信）: 上の比べ。
- 見ていない事: 枠に当たっている最中の本物の席（4行の画面）への送信。macOS・Windowsの実物。3番・4番を選んだ時の動き（打たない）。
