# ADR 0118: 席の環境へ、席の会話IDを入れる

状態: 採用。

## 原因

Aitermは、agentの席のprocessへ起動の印（`AITERM_AGENT_LAUNCH_ID`ほか`AITERM_AGENT_*`）を環境変数で渡す。席の中で動く道具（hookなど）は、
この印で「Aitermが起こした、呼び手が番の終わりを待っている席か」を見分けられる。

印は、席のprocessが起こした子にも継がれる（道具の子、そこから起こした別の会話、裏の会話）。印だけでは、席そのものの会話と、席から生まれた
別の会話を見分けられない。Aitermの側は、席の会話IDを自分の記録に持ち、別の会話IDの番の終わりを席の物と数えないが、その値は席の外から
読むしかなかった。

実例（2026-10-13）: 会話の引き継ぎの道具が、Aitermの席の会話を裏の会話へ引き継いだ。席は前の会話の画面のままで、呼び手の文は後継へ届かず、
後継の答えも呼び手へ戻らなかった。道具の側で「席そのものの会話では引き継がない」と決めるには、hookが受ける会話IDと比べる値が要る。

## 決めた事

- 席の環境へ `AITERM_AGENT_VENDOR_SESSION_ID`（席の会話ID）を入れる。**起動の時点で会話IDが決まっているharnessだけ**: Claude CodeとGrok
  （`--session-id`で渡す値と同じ）。CodexとCursorは、会話IDが起動の後に分かるので入れない（変数そのものを置かない）。
- 値は、席の記録の`vendor_session_id`と同じ。席の途中で変わらない。
- 読む側の決まり: この変数がある時は、自分の会話IDと同じ時だけ「席そのものの会話」と数える。無い時は、今までどおり起動の印だけで見る。
- 素の端末（`pty_open`）には、今までどおり`AITERM_AGENT_*`を入れない。

## 取らなかった形

- **席の記録のfileを道具に読ませる。** 製品がほかの製品の中のfileを直に読む形になる。置き場と形を変えられなくなる。
- **問い合わせの口（CLI）を足す。** hookのたびにprocessを1つ起こす事になる。環境変数は起こさずに読める。

## 確かめ

- `test/agent-vendor-session-env.test.mjs`: 偽の席が受けた環境の値が、起動の引数の`--session-id`と同じ。
- 本物の席（Linux、Claude Code 2.1.296）: 席のprocessの環境の値が、起動の引数と席の記録の両方と同じ。
- 見ていない事: macOS・Windowsの実物。Grokの実物。
