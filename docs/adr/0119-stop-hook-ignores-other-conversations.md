# ADR 0119: Claude CodeのStopのhookは、席の会話と違う会話では、席の記録に触らない

状態: 採用。

## 原因

Aitermは、Claude Codeの席のprocessへ起動の印（`AITERM_SESSION_ID`・`AITERM_AGENT_LAUNCH_ID`ほか）を環境変数で渡し、Stopのhookはその印で
席の記録の宛先を決める。印は、席のprocessが起こした子にも継がれる。Claude Codeの裏の会話（`claude --bg`）は、起こした側ではなく裏の常駐の
processの環境を継ぎ、常駐は最初に起こしたprocessの環境を持ち続ける（2.1.296、Linuxで確かめられた事実）。席の中から常駐が起きると、
その後の裏の会話は、席と関係が無くても席の印を持つ。

Stopのhookは、受けた会話ID（`session_id`）が席の会話かを確かめずに、次の3つをしていた。

1. 席の答えのfile（`…claude-result.json`）を、その会話の最後の文で上書きする。
2. 席のevent（`…events.jsonl`）へ`agent_done`を足す。
3. 席の番の印（`…claude-operation.json`）があれば消す。

完了を読む側は、会話IDが席の物と違うeventを捨てるので、2は害が無い。1は、席の番の答えを、呼び手が読む前に別の会話の文で置き換えうる。
3は、席の番が動いている最中に印を消し、次に届く文が差し込みでなく新しいturnの道で入る。

## 決めた事

- Stopのhookは、書く前に席の会話IDを確かめる。**席の会話と違う会話のStopでは、何も書かずに終わる**（答え・event・番の印のどれにも触らない）。
- 席の会話IDは、**席の記録（`…agent.json`の`vendor_session_id`）を先に読み**、無い・読めない時だけ、起動時に環境へ入れた値
  （`AITERM_AGENT_VENDOR_SESSION_ID`、ADR 0118）を見る。記録を先にするのは、環境の値はprocessが生きている間変えられず、席の会話を後から
  結び直す形を作った時に古い値のまま残るため。
- どちらも無い時は、今までどおり印だけで席の物と数える（古い記録の席、試験の最小の形）。

## 取らなかった形

- **完了を読む側で捨てるだけにする（今までの形）。** 答えのfileと番の印は、読む前に書き換わる。
- **環境の値だけで比べる。** 上のとおり、席の会話を結び直した後に、席そのもののStopを捨てる事になる。
- **Grokのhookにも同じ確かめを入れる。** Grokのhookはeventを足すだけで、答えのfileと番の印を持たない。読む側が捨てるので足りる。

## 確かめ

- `test/managed-stop-hooks.test.mjs`: 席の印を継いだ別の会話のStopで、席の3つのfileが変わらない事（席の記録がある時と、環境の値だけの時）。
  席の会話のStopは今までどおり書き、席の記録の会話IDを環境の値より先に見る事。
- 本物の席（Linux、Claude Code 2.1.296）: 1通を通して、席のStopがeventと答えを書く事。
- 見ていない事: 席の印を継いだ本物の裏の会話。macOS・Windowsの実物。
